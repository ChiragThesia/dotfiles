herdr + Ghostty + nvim

Every keybinding and deliberate modification in this setup, and why each one is what it is. macOS only — Ghostty.app, Homebrew and Option-key remapping are load-bearing throughout.

Overview

Three programs stacked on top of each other, each one deliberately giving up keys to the layer above it:

LayerRoleConfig
Ghosttythe terminal window~/.config/ghostty/config
herdrtabs, panes, workspaces, agent sidebar~/.config/herdr/config.toml
Neovimeditor, LazyVim-based~/.config/nvim/
zshshell, tool integrations, aliases~/.config/zsh/workflow.zsh
worktrunkgit worktree manager (wt)~/.config/worktrunk/config.toml

Everything is managed with chezmoi and kept in sync between machines by dotsync.

Install

brew install chezmoi
chezmoi init --apply chiragthesia/dotfiles

That installs everything brew-installable (Ghostty, worktrunk, zoxide, fzf, fd, eza, bat, lazygit, jq, bun, atuin, television, go-task), then herdr itself via its own installer, wires herdr's worktrunk plugin, merges a curated set of Claude Code settings, and installs the caveman and claude-hud plugins.

After the first apply: reload Ghostty once (⌘+⇧+, or quit and reopen) so the =unbind lines and theme take effect, and launch nvim once and wait — lazy.nvim bootstraps and Mason installs language servers on first real launch.

How the layers fit

A key pressed in the terminal is seen by Ghostty first. If Ghostty has its own action bound to that chord, herdr and nvim never see it. So the config works top-down: Ghostty unbinds a chord, which lets it fall through to herdr; herdr leaves ⌃+h/j/k/l alone, which lets it fall through to nvim.

ChordGhostty doesSo it reaches
⌘+tunbind (was: new Ghostty tab)herdr new_tab
⌘+wunbindherdr close_pane
⌘+⇧+wunbind (was: close window)herdr close_tab
⌘+kunbindherdr goto
⌘+dunbind (was: native split)herdr split_vertical
⌘+⇧+dunbind (was: native split)herdr split_horizontal
⌘+⇧+gunbindherdr lazygit popup
⌘+eunbindnvim <D-e> focus explorer
Ghostty's native splits are a separate, untracked terminal surface — herdr doesn't know about them. That's the same problem as ⌘+t opening a Ghostty tab instead of a herdr one, which is why both are unbound.

Language support

LazyVim extras enabled: neo-tree, typescript, python, rust, json, toml, markdown.

Python auto-activates a project .venv or venv by walking up from the current file — the equivalent of VS Code's "Select Interpreter". Pyright is kept for ⌃-click and hover but has typeCheckingMode = "off", so it doesn't surface type errors.

lazy-lock.json is committed, so plugin versions match what was actually tested rather than whatever is newest.

worktrunk

~/.config/worktrunk/config.toml

# Fires before branch resolution, for every entry point.
[pre-switch]
fetch = "git fetch origin --quiet"

Without that fetch, --create bases the new branch off whatever origin/<default> happens to point at locally, which can be stale. Worktrees go to the tool's own default sibling-directory location.

No [post-start] hooks ship here. Add your own if you want something to run on every worktree creation.

dotsync

One command to reconcile a machine with the repo, in both directions. 

dotsync                      # capture, ask, pull, apply
dotsync "commit message"     # same, with your own message
dotsync -y                   # push without asking
dotsync -n                   # never push this run; just pull and apply
  1. chezmoi re-add — pulls local edits to managed files back into the source repo
  2. Secret scan — a hit stops everything before it leaves the machine
  3. Asks before sending anything to GitHub (y / n / d for a diff)
  4. Pulls, reports which commits arrived and which files will change here, then applies
  5. Reloads herdr's config, and names anything else needing a restart
Declining the push still pulls and applies, so n keeps the machine up to date without publishing anything. Local edits stay uncommitted in the source repo until the next run.

A new file isn't picked up until it's registered once: chezmoi add ~/.config/nvim/lua/plugins/foo.lua. After that every edit to it syncs automatically.

Design notes

Why several bindings are what they look like, so they don't get "fixed" later.

Backtick, not §

The upstream layout this is based on uses §, an ISO-layout key that doesn't exist on US ANSI keyboards. Backtick sits in the same physical slot, so it's the closest translation.

Readline owns several Alt chords

In a shell, ⌥+b is backward-word, ⌥+d is kill-word and ⌥+r is revert-line. Binding those at the multiplexer level steals them from every shell in every pane. That's why splits use ⌘+d and rename uses ⌘+r.

This doesn't apply behind the prefix. Prefix mode claims the next keystroke itself, so ` then f never reaches the shell — which is why indexed agent focus can safely live at ` then ⌥+1…9. ⌥+b for the browser pane is the one deliberate exception.

Vertical means side-by-side

split_vertical puts panes left | right and split_horizontal stacks them top / bottom — matching vim and what these same keys already did as Ghostty's native splits before they were unbound.

Modifier families

  • ⌥+hjkl — move within (panes)
  • ⌥+⇧+hjkl — move across (agents on h/l, workspaces on j/k)
  • ⌥+⇧+arrows — reorder rather than navigate
  • `then⇧ — the rarer or more destructive variant of a chord

Two worktree systems, on purpose

herdr has native worktree creation and worktrunk is a separate tool. The worktrunk plugin took herdr's default chord, so the native modal was given ⌥+⇧+g back. They keep separate directories and don't interfere.
